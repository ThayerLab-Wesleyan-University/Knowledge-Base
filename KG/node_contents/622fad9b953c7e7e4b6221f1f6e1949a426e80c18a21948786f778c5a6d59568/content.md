# gRINN

**Verified in original document:** 2026-09-21

These need to be separated because the original **gRINN** and the current **i-gRINN** are related but not the same software deployment.

## What it is

**gRINN** stands for **get Residue Interaction eNergies and Networks**.

It is standalone software designed specifically for:

> pairwise residue interaction-energy analysis of protein MD trajectories and construction of protein energy networks.

The original version was implemented in Python 2.7 and bundled GUI / scientific-Python components, but users generally interacted with it as standalone software rather than as a modern reusable Python package API.

## Core function: residue-pair nonbonded energies

For residue pair `(i, j)`, gRINN extracts force-field-based nonbonded interactions, specifically:

- **electrostatic interaction energy**;
- **van der Waals interaction energy**;
- total pairwise nonbonded interaction energy.

Critically, gRINN itself does not define its own force field. It drives external MD engines.

The original software supported trajectories generated by:

- NAMD / CHARMM-style workflows;
- GROMACS.

It repeatedly invokes the appropriate MD executable to extract pairwise energies.

## Interaction-energy time series

For residue pairs, gRINN can produce:

```text
E_ij(t)
```

rather than only one static structural value.

Outputs include time series and averages.

## Interaction Energy Matrix (IEM)

A residue-by-residue matrix can be constructed from averaged interaction energies:

```text
IEM[i,j] = average interaction energy between residues i and j
```

## Correlations between interaction-energy time series

gRINN can calculate equal-time linear correlations between interaction-energy series.

Conceptually:

```text
corr(E_ij(t), E_kl(t))
```

It then projects interaction-correlation information back to residue space to construct residue-correlation measures.

## Protein Energy Networks (PENs)

Residues become nodes and energetically defined relations become weighted edges.

gRINN includes network analysis such as:

- degree;
- betweenness centrality;
- closeness centrality;
- shortest paths.

The aim is to identify:

- stabilizing interactions;
- energetically important residues;
- communication pathways;
- possible allosteric relations.

## Visualization / output

The original tool includes GUI-based visualization for:

- energy time series;
- distributions;
- interaction energy matrices;
- correlations;
- residue correlation matrices;
- network analyses.

It also writes tabular data such as CSV files that can be used in custom downstream analysis.

## Current status

The legacy gRINN documentation now explicitly warns that the old standalone version is not maintained for current GROMACS/NAMD / operating-system compatibility and recommends the new i-gRINN system.

## What gRINN/i-gRINN do **not** do

Their central scientific goal is not:

- CNN representation learning;
- recurrent neural modeling;
- VAMPNet learning;
- self-supervised future-state prediction;
- mutation classification.

They produce physically meaningful residue-level energetic information and network analyses.

## Relationship to SAWNERGY

This is arguably the **closest overlap with SAWNERGY's pairwise-energy preprocessing**.

If SAWNERGY's contribution were only:

> “compute residue-by-residue electrostatic and vdW interaction energies from an MD trajectory,”

then that idea already exists very clearly in gRINN/i-gRINN.

The possible SAWNERGY distinction would instead be:

```text
force-field residue-pair energies
        +
other relation channels (distance, H-bond, contact, ...)
        +
full time-resolved tensor representation
        +
neural spatial/temporal learning
        +
careful biological validation
```
